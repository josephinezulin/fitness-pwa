## E1：公開影片縮圖快取

## E9：常做的運動再記一次

總覽最近紀錄與運動紀錄頁新增「再記一次」。帶入來源的類型、分鐘、備註及每一段跑步機速度／坡度，作為可修改的新草稿；戶外快走／慢跑保留非跑步機模式。日期使用既有工作區的今天（雲端採試算表時區），來源日期只放在提示，不當作新紀錄日期。舊 ID、熱量與影片觀看 metadata 不複用，新 ID 只於儲存建立；熱量起始為 0，提醒依本次活動填寫或明確套用估算。

草稿由 App 協調，總覽與完整紀錄共用 callback／權限檢查；換帳號／副本沿用既有清草稿與關閉表單機制。分段陣列及各物件複製後才交給表單，改值或取消不動來源。只有確認儲存才走既有本機／雲端新增與 outbox；不自動完成紀錄、不替影片加觀看次數，不新增 Sheet 分頁、API、OAuth scope 或草稿持久儲存。這是以既有紀錄作為填寫起點，個人自訂跑步機範本的獨立雲端清單仍未加入。

官方方案依據：React 建議陣列與內部物件以新副本更新，相關元件共享的狀態由共同父層協調。沿用 App 的草稿生命週期，沒有另建跨帳號的範本快取。

## E14：PWA 回前景檢查新版並驗證真實升級

先前只在元件掛載時註冊 Service Worker，長時間不關閉的主畫面 PWA 可能繼續使用舊介面。現在由已註冊的 worker 在 window focus、online 或 document visibilitychange 時嘗試 update()；只在畫面可見且有網路、沒有安裝／等待中的 worker 時執行。註冊已自行檢查一次，因此事件檢查設 60 秒冷卻，同時只容許一個進行中請求；沒有 setInterval、背景排程或喚醒手機。

## E15：跨分頁啟用新版時保留目前草稿

新增真實雙分頁測試並在舊版重現失敗：A 頁開運動表單填入虛構備註，B 頁啟用新版 worker 後，A 頁的表單與備註消失。檢查已安裝的 Vite PWA 0.21.2 註冊實作，發現其更新提示會加入 controlling 後自動 reload 的處理；按鈕雖停用，其他分頁啟用仍可觸發此路徑。

改由 `pwa-registration.ts` 使用瀏覽器原生 register、updatefound、worker statechange 與 controllerchange。維持相同的 sw.js 網址、repo 子路徑 scope 與 Vite／Workbox 產生的 worker／快取策略；沒有新增依賴、另寫快取實作、改成自動 skipWaiting、解除註冊或清除資料。應用不再載入 virtual:pwa-register 的自動重載處理，正式產物也不再有 workbox-window 網頁端 chunk；worker 內的 Workbox 仍保留。

安裝新版只顯示就緒；目前頁明確按更新才傳 SKIP_WAITING。另一頁啟用造成 controller 改變時，只通知目前頁可更新，不自動重載。即使 waiting 已消失，之後按更新仍可直接重載到已啟用的介面。目前頁自己的啟用完成時，也重新檢查最新 blocked ref，避免按更新之後又開表單的競態；若鎖定便保留提示，準備好後再按一次。初次安裝的首次控制不當作更新，離線就緒在初次啟用後回報；註冊失敗、postMessage 失敗可正常提示／重試，卸載清理所有自訂監聽並忽略晚到的結果。

官方資料說明 controllerchange 代表當頁 controller 改變，updatefound 可找到新安裝中的 worker，而 skipWaiting 會讓新 worker 開始控制先前頁面。因此把「啟用共用 worker」與「重載個別頁面」分開；只由目前頁明確要求並通過工作鎖才重載。E14 的可見／連線／60 秒冷卻檢查仍沿用。

## E19：影片搜尋、長度篩選與分批閱讀

## E20：影片清單的舊分頁寫入保護

接續 E19 查找改善時，以元件測試重現兩個資料保護缺口：A 頁開著影片新增草稿，B 頁先存入影片後，A 頁儲存會用舊清單覆蓋 B 的影片；而原始清單無法解讀時，原本會悄悄回到空清單且仍允許新增。本輪兩個案例在修改前均失敗，修改後通過。

提示中的「重新讀取影片清單」需先關閉影片新增／編輯表單才可使用。先自行複製需要的草稿，再關閉表單並明確讀取；成功後更新清單與原始內容基準，保留目前搜尋／篩選／批次及 iframe 節點，不自動合併草稿。讀取失敗保留原畫面及阻擋狀態，可在權限恢復或有效備份還原後重試；無法解讀的內容不當作可寫入的空清單。寫入空間不足時保留來源與草稿，空間恢復後可重試。提示改用直向排列，文字 14px、重新讀取按鈕至少 44px，避免手機上擠在同一列。

## E21：直接編輯本機自訂影片

本機自訂影片原先只能新增或移除，修改名稱／長度需要重建一筆。本輪先用元件測試確認舊介面找不到本機影片編輯入口，再新增卡片上的「編輯影片」按鈕與 editVideo。只可編輯自訂紀錄，內建影片仍以隱藏方式管理；雲端影片沿用現有 callback 與權限，不把本機自訂影片混入雲端帳號。

開啟新增或編輯表單時，原生 URL 欄位取得焦點，手機可直接輸入；編輯另一筆以既有 key 重新建立表單，不把上一筆輸入混用。取消不寫入；失敗保留草稿。成功的本機新增／編輯清除原搜尋、長度與收藏篩選並選取儲存分類，依原順序展開到足以顯示該筆的 12 部批次，把焦點移到儲存後標題；即使從搜尋找到很舊的影片，也不會儲存後被首批藏住。只增加 DOM 呈現範圍，並未變動來源順序。

新增只留目前元件的 opener、名稱欄位與標題 ref，在開啟狀態變更的 layout 階段定位。新增／編輯時聚焦名稱並即時捲到視窗中央；取消或既有 onSave 成功返回後，回到仍連線且可操作的原按鈕，包含更名後同 ID 的列。若原列被外部移除或權限改變使按鈕停用，改回可程式聚焦的「管理課表」標題。普通重新渲染、失敗儲存及遠端衝突不搬焦點、不清草稿；卸載不將焦點拉回舊工作區。沒有焦點陷阱或自訂 Tab／Escape 攔截，沿用行內表單的原生順序。

管理區域與新增／編輯表單各以標題具名；入口以 aria-expanded 呈現目前狀態，表單存在時用 aria-controls 關聯。課表標籤、輸入及選單共用運動對話框的既有欄位樣式，16px 輸入、至少 44px 高度、可縮窄雙欄；核取方塊保留水平標籤及至少 44px 點按列。課表新增、編輯、啟用／停用與取消按鈕至少 44px，規則限定 plan-manager。沒有改動健康曲線、頁面溢位策略、縮放權限、資料格式、儲存 key、依賴、Sheets、OAuth scope 或 API；仍需明確儲存才寫入，沿用原權限、遠端衝突與 PWA 草稿保護。

官方依據（2026-11-08 實際讀取）：WCAG Focus Order 說明動態介面的焦點順序應保留意義與操作性；MDN focus 說明 preventScroll 可將聚焦與捲動分開。本輪僅在明確進出表單時移動焦點，以即時 center 捲動避開已觀察的固定底部介面；不將自動捲動或 Chromium DOM 斷言當成 VoiceOver／Safari 軟鍵盤驗收。

- https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html
- https://developer.mozilla.org/en-US/docs/Web/API/HTMLElement/focus

手動方式：iPhone 在「本週課表」新增或編輯一個課表，確認名稱欄位可見、標籤不與欄位擠成一行，雙欄不超出畫面；外接鍵盤可用 Tab／Shift+Tab。填虛構名稱後取消應回原編輯按鈕、不修改課表；離線儲存後應回更名後的同一列，重開仍保留。新增表單取消回新增按鈕。VoiceOver 需另外確認具名區域／表單與展開狀態、軟鍵盤出現後的欄位可見性；此項未在實機完成。不需新的 Google 授權。

限制：這仍是清單下方的行內表單，不是浮動對話框；名稱欄位居中不代表 iOS 軟鍵盤／安全區與 VoiceOver 的實際行為已驗收。取消只關閉目前草稿，失敗保留；外部已移除的原按鈕以標題作返回位置。既有跨裝置衝突限制與健康捷徑待辦保持不變。

## E27：跑步機明細限制高度與下方收合

接續使用者對長內容限制高度、方便收合的需求，檢查既有跑步機明細。在 320px Chromium 先重現 50 段展開區高達 1,667px，統計與整張表一次撐高頁面，捲到底後必須回到摘要才能關閉。

以 segment-detail-scroll 包住統計與完整表格，最大高度為 min(320px, 50svh)，並保留 50vh fallback；overflow:auto、overscroll-behavior:contain，只捲動明細，摘要與新增的下方收合按鈕留在區域外。保持每一段原值與順序，沒有截斷、分頁或改用摘要取代原始表格；表格使用 13px 數值、固定欄寬與固定欄名，caption 說明總段數，th scope 分別標示列與欄。一般運動與短分段沿用相同紀錄流程，統計公式及健康曲線不變。

捲動區具日期／類型名稱、role=region、tabIndex=0 與可見焦點框，摘要在展開時以 aria-controls 關聯當前區域。區域後方的「收合分段明細」至少 44px，可由原生 Tab 到達，Enter 啟用後聚焦原紀錄的摘要並即時定位；不攔截鍵盤。原本摘要仍可切換開關，唯讀時查看與收合不受編輯權限限制。DOM 關聯使用元件 ID 與顯示列序，不把原始 workout ID 直接當含空白的 IDREF。ref 隨按鈕卸載清理，不新增儲存或跨頁狀態。

官方依據（2026-11-08 實際讀取）：MDN overflow 建議對需要鍵盤操作的捲動容器使用 tabindex=0，並以區域角色及可存取名稱交代上下文；W3C 表格教學以 th scope=row／col 與 caption 保留資料表關聯。沿用既有趨勢數值清單的高度策略，不隱藏整頁溢位或限制縮放。
